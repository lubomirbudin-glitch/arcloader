# Offload — vestavěné LUTy pro proxy a náhledy (Mac i Windows)

Datum: 2026-10-05 · Stav: ke schválení · Plán 5 (Windows), Mac podle stejného návrhu

## 1. Cíl

Proxy a náhledy v reportu z logových záznamů mají vypadat přirozeně bez toho, aby si uživatel hledal LUT.
Aplikace má **vestavěné LUTy Log → Rec.709** pro běžné kamery a **sama vybere** ten správný podle metadat
klipu; když kameru nepozná, použije LUT vybraný v seznamu. Vlastní `.cube` jde vybrat jako dosud.

### Rozhodnutí (odsouhlaseno 2026-10-05)

| Otázka | Rozhodnutí |
|---|---|
| Kamery / profily | všechny nabídnuté: ARRI LogC3 + LogC4, Sony S-Log3 (S-Gamut3.Cine i S-Gamut3), Blackmagic Film Gen 5, RED Log3G10 / REDWideGamutRGB, Canon C-Log2 + C-Log3, Panasonic V-Log, DJI D-Log, Fujifilm F-Log2 |
| Výběr | automaticky podle metadat klipu + ruční výběr ze seznamu jako záloha + vlastní `.cube` |
| Světla | měkké dotočení světel (jemná S-křivka), ne čistě technický převod |
| Původ LUTů | vlastní výpočet z veřejných specifikací výrobců (oficiální LUTy výrobců se nepřibalují — licence nedovolují je šířit) |

### Mimo rozsah

- Kreativní looky, film emulace, HDR výstup (PQ/HLG), ACES.
- DJI **D-Log M** (Mavic 3, Air 3, Osmo): DJI křivku nezveřejnilo — bez vestavěného LUTu (jde vybrat vlastní `.cube`).
- Úprava expozice nebo vyvážení bílé podle metadat.

## 2. Sdílené LUTy (`shared/luts/`)

LUTy jsou společné pro obě verze, aby Mac i Windows proxy vypadaly stejně.

```
shared/luts/
  generate.py            generátor (Python 3.10+, colour-science 0.4.6 — zafixovaná verze)
  requirements.txt       colour-science==0.4.6, numpy
  README.md              jak generovat, zdroje, ověřovací body
  ARRI_LogC3_AWG3_to_Rec709.cube
  ARRI_LogC4_AWG4_to_Rec709.cube
  Sony_SLog3_SGamut3Cine_to_Rec709.cube
  Sony_SLog3_SGamut3_to_Rec709.cube
  Blackmagic_FilmGen5_WideGamutGen5_to_Rec709.cube
  RED_Log3G10_RWG_to_Rec709.cube
  Canon_CLog2_CinemaGamut_to_Rec709.cube
  Canon_CLog3_CinemaGamut_to_Rec709.cube
  Panasonic_VLog_VGamut_to_Rec709.cube
  DJI_DLog_DGamut_to_Rec709.cube
  Fujifilm_FLog2_FGamut_to_Rec709.cube
  luts.json              katalog: id, název pro UI, soubor, log křivka, gamut, výrobce
```

- `.cube` soubory se generují jednou a **commitují** — build ani aplikace Python nepotřebují. Generátor je
  deterministický (stejný vstup → stejné bajty); test v CI-like kroku ověří, že commitnuté soubory odpovídají
  generátoru.
- Formát: `LUT_3D_SIZE 33`, `DOMAIN_MIN 0 0 0`, `DOMAIN_MAX 1 1 1`, hodnoty na 6 desetinných míst, `TITLE` s názvem
  a hlavička `# Offload built-in LUT, generated by shared/luts/generate.py (colour-science 0.4.6)`.
- **Vstup LUTu = RGB tak, jak ho dá ffmpeg po převodu videa do RGB** (`format=rgb48le` rozšíří legální rozsah
  64–940 na 0–1): vstup `x` odpovídá 10bitovému kódu `x·876 + 64`. Tak se chovají i LUTy výrobců v Resolve.
  Snímky z RAW dekodérů (BRAW, R3D, ARRIRAW) a videa s plným rozsahem (`color_range=pc`) mají kód v plném rozsahu
  (`kód / 1023`) — před vestavěným LUTem se přepočítají filtrem `lutrgb` na stejnou konvenci (`x = (v·1023 − 64) / 876`).
  Vlastní `.cube` od uživatele se aplikuje beze změny jako dosud.
- Výstup = Rec.709 (BT.1886, gama 2,4 pro zobrazení), plný rozsah.

### 2.1 Výpočet jedné buňky

1. **Log → scénické lineární světlo** — log dekódování z colour-science (`log_decoding` / `oetf_inverse` pro
   „Blackmagic Film Generation 5“) s parametry výrobce (ARRI LogC3 pro EI 800).
2. **Gamut kamery → Rec.709 (lineární)** — `colour.RGB_to_RGB` mezi prostorem kamery (ARRI Wide Gamut 3/4,
   S-Gamut3.Cine, S-Gamut3, Blackmagic Wide Gamut, REDWideGamutRGB, Cinema Gamut, V-Gamut, DJI D-Gamut,
   F-Gamut) a ITU-R BT.709; všechny mají bílý bod D65, takže bez chromatické adaptace.
3. **Mimo gamut** — záporné složky se ořízne na 0 (jednoduché, předvídatelné).
4. **Měkké dotočení světel** (po složkách, scénické lineární `L` → zobrazovací lineární `y`):
   - expozice `g = 0,42^2,4 / 0,18` (18% šedá → výstupní kód přesně **0,42**, typická šedá „709“ LUTů výrobců),
   - `x = g·max(L, 0)`; pod kolenem `k = 0,5` (≈ +1,9 stopy nad šedou) `y = x`,
   - nad kolenem rameno `y = k + (1 − k)·(1 − e^(−(x − k)/(1 − k)))` — spojité i se směrnicí, monotónní, k 1,0
     (+6 stop nad šedou → výstup ≥ 0,98),
   - konstanty jsou v `generate.py` a `README.md`, testy hlídají vlastnosti níže.
5. **Rec.709 zobrazení** — inverzní BT.1886 (`x^(1/2,4)`), oříznutí na 0–1.

### 2.2 Ověřovací vlastnosti (testy generátoru)

Pro každý LUT:
- 18% šedá (zakódovaná logem kamery) → výstup R = G = B ∈ [0,41; 0,43].
- Černá kamery (kód černé dané křivky) → výstup ≤ 0,02.
- Neutrální vstupy (R = G = B v logu) → neutrální výstup (odchylka složek ≤ 0,002).
- Výstup monotónní podél šedé osy, v rozsahu 0–1, bez NaN.
- Logový bílý bod +6 stop → ≥ 0,98, nic se „nepřeklopí“ (žádný pokles jasu se stoupající expozicí).
- Kontrolní body log dekódování proti hodnotám z bílých knih výrobců (např. LogC3 0,391007 → 0,18;
  S-Log3 0,41055718 → 0,18) — v README tabulka zdrojů.

## 3. Automatický výběr LUTu podle klipu

Nový modul `LutResolver` (Core na Windows, OffloadKit na Macu, stejná pravidla). Vstup: `Clip`, `ClipInfo`
(ffprobe), postranní metadata karty, výsledek RAW dekodéru. Výstup: `LutChoice` = (id vestavěného LUTu |
cesta vlastního | žádný, **důvod** pro report).

Pořadí pravidel (první platné vyhrává):

| Zdroj | Pravidlo | Spolehlivost |
|---|---|---|
| Sony XAVC (FX3/FX6/FX9/Venice/A7S…) | postranní `…M01.XML` (NonRealTimeMeta) vedle klipu: `CaptureGammaEquation` = `s-log3-cine` / `s-log3`, `CaptureColorPrimaries` = `S-Gamut3Cine` / `S-Gamut3` → Sony LUT podle gamutu; jiná křivka (`rec709`, `hlg…`, `s-cinetone`) → **žádný LUT** | vysoká |
| ARRI (MXF/MOV ProRes, ARRIRAW) | metadata kamery (ffprobe tagy / art-cmd `LogEncoding`, model kamery): ALEXA 35 → LogC4, ostatní ALEXA/AMIRA → LogC3; ARRIRAW se dekóduje do logu (`--target-colorspace AWG…/LogC…`) a LUT se aplikuje stejně | vysoká pro ARRIRAW, střední pro ProRes (ověřit na vzorku) |
| Blackmagic RAW | dekodér BRAW předá gamma/gamut klipu; „Blackmagic Design Film“ Gen 5 → BMD LUT; klip nahraný v „Video“ gamě → **žádný LUT** | vysoká (po plánu 3) |
| RED R3D | REDline se vždy nastaví na IPP2 / REDWideGamutRGB / Log3G10 (jako dnes s LUTem) → RED LUT | vysoká |
| Canon, Panasonic, DJI, Fujifilm | pravidla podle ffprobe tagů / postranních XML **se doplní podle ukázkových klipů** (uživatel dodá vzorky); do té doby se tyto kamery nepoznají automaticky | nízká → ruční výběr |
| nic nepasuje | **záložní volba** ze seznamu (výchozí „bez LUT“) | — |

- Pravidla jsou čisté funkce nad daty (testovatelné bez souborů kamer; fixture XML/JSON v testech).
- Vlastní `.cube` (ruční výběr) má přednost před automatikou jen když uživatel zvolí „Vlastní…“ místo
  „Automaticky“.
- Jeden klip = jeden LUT; na kartě mohou být klipy z různých kamer (každý dostane svůj).

## 4. UI, CLI, report

- **GUI, sekce Proxy, řádek LUT** — rozbalovací seznam:
  „Automaticky podle kamery“ (výchozí) · jednotlivé vestavěné LUTy (název z `luts.json`, např. „Sony S-Log3 /
  S-Gamut3.Cine → Rec.709“) · „Bez LUT“ · „Vlastní…“ (dialog `.cube`, jako dnes).
  Při „Automaticky“ druhý seznam **„Když kameru nepoznám:“** (Bez LUT / vestavěný LUT / vlastní).
  LUT se uplatní na proxy i na 3 snímky v reportu (náhledy už dnes LUT používají).
- **Nastavení** (`settings.json`, Mac `AppSettings`): v `proxy` nové klíče `lutMode` (`"auto" | "builtin" | "custom" |
  "none"`), `lutBuiltin` (id), `lutFallback` (id nebo `null`); stávající `lutPath` zůstává pro vlastní LUT.
  Starý soubor jen s `lutPath` → `lutMode = "custom"`; bez `lutPath` → `"auto"` s fallbackem „bez LUT“.
- **CLI** — `--lut auto` (výchozí, když je zapnutá proxy nebo analýza), `--lut <id>` (vestavěný, např. `sony-slog3-sgamut3cine`),
  `--lut <cesta.cube>`, `--lut none`; `--lut-fallback <id|none>`.
- **Report** (JSON/HTML/PDF, formát společný): u klipu nový volitelný klíč `lut` = `{ "id": …, "name": …,
  "source": "auto|builtin|custom|none", "reason": "Sony XML: s-log3-cine / S-Gamut3Cine" }`; HTML u klipu řádek
  „LUT: Sony S-Log3 / S-Gamut3.Cine → Rec.709 (podle XML kamery)“. Starší reporty bez klíče zůstávají platné.
  Zápis do `docs/FORMATY.md`.

## 5. Přibalení

- Windows: `build.ps1` zkopíruje `shared/luts/*.cube` + `luts.json` do `Offload\luts\`; aplikace a CLI je hledají
  vedle exe (`luts\`, při vývoji v repu `shared\luts`).
- Mac: `build-app.sh` je přibalí do `Offload.app/Contents/Resources/luts/`; CLI je hledá vedle sebe stejně.
- Chybějící složka `luts` → vestavěné LUTy nejsou v nabídce, automatika vrací „bez LUT“ s důvodem
  „vestavěné LUTy chybí“ (nikdy nepadne).

## 6. Testování

1. Generátor (Python): vlastnosti z 2.2 pro každý LUT; determinismus; commitnuté soubory = výstup generátoru.
2. Načtení `.cube` (Windows i Mac): hlavička, velikost, rozsah — sdílená sada testů (`LutCatalog`).
3. `LutResolver`: fixture Sony XML (S-Log3 Cine, S-Log3, rec709, chybějící), ARRI tagy (ALEXA 35 / Mini LF /
   neznámý), BRAW gamma (Film Gen 5 / Video), RED, nic → fallback; vlastní LUT přebíjí automatiku jen v režimu „Vlastní“.
4. Proxy pipeline: syntetický klip zakódovaný S-Log3 (ffmpeg `lut3d` s inverzním LUTem není nutný — stačí
   klip s šedou 0,41 a XML) → proxy má šedou ~0,42; report obsahuje `lut`.
5. Ruční: uživatel dodá vzorky z kamer (Sony, ARRI, Canon, Panasonic, DJI, Fuji, BRAW) → doplní se pravidla
   pro kamery s nízkou spolehlivostí a ověří se vzhled proxy.

## 7. Blackmagic RAW na Windows (změna plánu 3)

Rozhodnuto 2026-10-05: dekodér BRAW pro Windows se napíše **v C#** (ne port C++ nástroje). Použije
Blackmagic RAW SDK pro Windows (COM rozhraní `BlackmagicRawAPI.dll`); uživatel stáhne a nainstaluje SDK —
Visual Studio C++ nástroje nejsou potřeba. Dekodér předá snímky ffmpegu stejně jako Mac `braw-decode` (surové
snímky přes rouru) a metadata (gamma, gamut) pro `LutResolver`. Podrobnosti v plánu 3 (po instalaci SDK).
